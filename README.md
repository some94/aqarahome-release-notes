# Aqara Home 릴리즈 노트

루미(Lumi) 본사가 메일로 보내는 **Aqara Home 앱 릴리즈 노트**를 자동으로 모아 한국어로 번역하고, 버전별로 검색할 수 있게 정리합니다.

- **웹 뷰어(팀원용)**: https://script.google.com/a/macros/aqara.kr/s/AKfycbyf_6Gkug_yj51P5CzGm4tNp1y-an81oRpFXmgkQ_Xto0D9w_b_c3w1K628Gd6UgQq9/exec
  - aqara.kr 계정으로 로그인해야 열립니다. 시트 공유 권한은 필요 없습니다.
- 데이터 저장소: Google 스프레드시트 "Aqara Home 릴리즈 노트"(운영자 소유) — 탭: 버전·항목·용어집·실행 로그
- 동작: 매주 1회 자동 수집(Gmail 읽기 전용) → 메일 파싱 → Claude로 번역 → 시트 저장 → 뷰어에 반영

> ⚠ 메일에는 **내부용(internal use only)** 내용이 있습니다. 뷰어·시트의 <kbd>내부용</kbd> 표시 항목은 사외에 공유하지 마세요.

## 팀원 안내

### 웹 뷰어 사용법
- **목록**: 최신 버전부터. 카드에 승인일, 채널별 상태(Android/iOS/Google Play), 항목 수, 내부용 항목 수가 보입니다.
- **상세**: 개요 → 공개 릴리즈 노트 → 기능 상세(내부용) → 온라인 이슈 수정 → 출시 일정·채널 → 버전 → 기타 순서. 하위 항목은 들여쓰기로 표시됩니다.
  - 각 항목의 **원문 보기**로 영어(중국어) 원문을 펼칠 수 있습니다.
  - "원본 메일 — Gmail에서 열기"는 수집 계정 메일함 기준이라 다른 계정에서는 열리지 않을 수 있습니다.
- **검색**: 한국어 번역, 영어 원문, 기기명, 기능 태그, 플랫폼을 한꺼번에 찾습니다.
  - 예: `카메라`, `W200`, `Matter`, `camera`, `자동화 iOS`
  - 여러 단어는 **모두 포함**하는 항목만 나옵니다(AND).
  - 검색 중에는 일치한 항목만 보이고, 흐리게 보이는 항목은 그 상위 항목(맥락)입니다. "이 버전 전체 보기"로 전체를 볼 수 있습니다.
- **필터**: 플랫폼(전체(AOS+iOS)·AOS·iOS — AOS·iOS는 그 OS로 표시된 항목만, 공통 제외), 섹션, 관련 기기, 승인일 기간, 내부용만.
- **링크 공유**: 주소창의 URL에 선택한 버전·검색어가 들어갑니다(예: `…/exec?v=6.3.6&q=W200`). 그대로 복사해서 공유하면 같은 화면이 열립니다.
- 상단 끝의 `(1.3초 · 서버 0.1초)`는 불러오는 데 걸린 시간입니다. 데이터는 최대 6시간 캐시되며, 시트가 바뀌면 바로 새로 읽습니다.

### 시트에서 번역 고치기 (시트 편집 권한이 있는 사람)
1. **항목** 탭에서 해당 행의 `한국어` 칸을 고칩니다.
   - `수정 여부`가 자동으로 체크됩니다. 체크된 항목은 이후 자동 재번역에서 **덮어쓰지 않습니다**.
2. 기계 번역으로 되돌리려면 `한국어` 칸을 비우고 `수정 여부` 체크를 풀고, 그 행을 선택한 뒤 **릴리즈 노트 → 선택 항목 재번역**을 실행합니다.
3. 용어 표기(제품명 영문 유지 등)는 **용어집** 탭에서 고칩니다. `원어`·`한국어 표기`·`비고`를 수정·추가하면 **이후 번역부터** 반영됩니다(이미 번역된 항목은 "선택 항목 재번역").
4. 버전 탭의 `처리 상태`가 `검수 필요`이면 `경고` 열에 원인과 항목 ID가 적혀 있습니다. 해당 항목을 확인·수정한 뒤 `처리 상태`를 `정상`으로 바꿔 주세요.

| 선택 항목 재번역 | 항목 탭에서 선택한 행을 다시 번역. 사람이 고친 항목이 섞이면 덮어쓰기/건너뛰기 선택 |
| 설정 점검 | 계정, Gmail 연결, 트리거, 진행 상태, 탭별 데이터 수, Script Properties(비밀값은 설정 여부만) |
| 관리 → 번역 테스트(버전 1개) | 한 버전만 번역하고 요청별 응답 시간을 표시 |
| 관리 → 백필 미리보기 | 전체 메일 파싱 결과만 보여줌(시트에 쓰지 않음). 키워드 제외 메일·추출 실패 메일 목록 포함 |
| 관리 → 백필 실행 | 전체 메일을 오래된 순으로 처리(저장된 버전은 건너뜀) |
| 관리 → 저장된 버전 재파싱 | 버전 하나를 원본 메일에서 다시 읽음. 사람이 고친 항목이 있으면 중단 |
| 관리 → 초기 설정(탭·헤더) | 탭·헤더·서식 생성·복구(여러 번 실행해도 안전, 트리거는 만들지 않음) |
| 관리 → 주간 자동 수집 설치·갱신 | 주간 트리거를 1개로 설치(요일·시각을 바꾼 뒤에도 다시 실행) |
| 관리 → 테스트 데이터 초기화 | 백업 후 버전·항목·실행 로그를 비움("초기화" 입력 필요) |

### 자동 수집
- 매주 **월요일 9시대**(Asia/Seoul)에 실행됩니다. 시간이 6분을 넘으면 1분 뒤 자동으로 이어서 처리합니다.
- 오류나 `검수 필요`가 생기면 **운영자(스크립트 소유자)에게 메일**이 갑니다. 결과는 **실행 로그** 탭에 남습니다.
- 메일은 **읽기만** 합니다(수정·삭제·라벨 변경 없음). 제목에 키워드가 없거나 회신(`Re:`, `回复：`)인 메일은 본문을 열지 않습니다.

### Script Properties
스크립트 편집기 → ⚙ 프로젝트 설정 → 스크립트 속성. 값이 없으면 기본값을 씁니다.

| 키 | 용도 | 기본값 |
|---|---|---|
| `ANTHROPIC_API_KEY` | Claude API 키 (**필수**, 코드·저장소에 넣지 말 것) | 없음 |
| `CLAUDE_MODEL` | 번역 모델 | `claude-sonnet-5-5` |
| `CLAUDE_EFFORT` | 번역 깊이(low~max) | `low` |
| `TRANSLATE_BATCH_SIZE` | 번역 요청 1회당 항목 수 | `20` |
| `GMAIL_QUERY` | 메일 검색 조건(라벨 기반으로 바꿀 수 있음) | `from:appupdate@aqara.kr OR to:appupdate@aqara.kr` |
| `SUBJECT_KEYWORDS` | 제목 키워드(쉼표 구분) | `release,notice,notification` |
| `TRIGGER_WEEKDAY` / `TRIGGER_HOUR` | 자동 수집 요일·시각(바꾼 뒤 "주간 자동 수집 설치·갱신") | `MONDAY` / `9` |
| `CHAT_WEBHOOK_URL` | (선택) 새 버전을 구글 챗으로 알림 | 없음 |
| `SPREADSHEET_ID`, `RUN_STATE`, `LAST_PROCESSED_AT` | 코드가 관리 — 직접 고치지 마세요 | |

비용 참고: 버전 1개(항목 10~60개) 번역은 수 센트, 2024-12 ~ 2026-09 전체 백필(항목 656개)은 약 $1.1였습니다.

## 최초 설정 (운영자를 새로 맡거나 다른 PC에서 개발할 때)

Windows PowerShell 기준입니다.

1. 준비물: Node.js 20 이상, Git
2. 저장소 받기 → 패키지 설치
   ```powershell
   git clone https://github.com/some94/aqarahome-release-notes.git; cd aqarahome-release-notes; npm install
   ```
3. clasp 설치·로그인 — **릴리즈 메일을 받는 aqara.kr 계정**으로 로그인합니다(브라우저 인증).
   ```powershell
   npm install -g @google/clasp; clasp login
   ```
4. https://script.google.com/home/usersettings 에서 **Google Apps Script API**를 "사용"으로 켭니다(꺼져 있으면 push 실패).
5. 스크립트 연결: `.clasp.json`은 저장소에 없으므로 직접 만듭니다. 스크립트 ID는 시트 → 확장 프로그램 → Apps Script → ⚙ 프로젝트 설정 → "스크립트 ID".
   ```json
   { "scriptId": "<스크립트 ID>", "rootDir": "dist" }
   ```
   (완전히 새로 만들 때는 `clasp create-script --type sheets --title "Aqara Home 릴리즈 노트" --rootDir dist` — 내 드라이브에 새 시트가 생깁니다.)
6. 코드 올리기: `npm run push`
7. 시트를 새로고침 → **릴리즈 노트 → 관리 → 초기 설정(탭·헤더)** → 권한 승인(Gmail 읽기, 스프레드시트, 외부 요청, 메일 발송, 트리거, 이메일 주소)
8. Script Properties에 `ANTHROPIC_API_KEY` 입력(위 표)
9. 데이터가 비어 있으면 **관리 → 백필 미리보기**로 확인 → **관리 → 백필 실행**
10. 웹앱 배포
    - 처음 배포: `npm run deploy -- --create` → 생긴 `deploy.config.json`을 커밋
    - 이후 배포: `npm run deploy` (같은 URL에 새 버전, 접근은 aqara.kr 도메인만·배포자 권한 실행)
11. **관리 → 주간 자동 수집 설치·갱신** → **설정 점검**에서 트리거가 `scheduledCollect 1개`인지 확인

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 새 버전이 `번역 대기`에 머묾 | 설정 점검의 `ANTHROPIC_API_KEY`, 실행 로그의 오류 내용. 키를 고친 뒤 "지금 수집"을 실행하면 이어서 번역 |
| `검수 필요` 메일을 받음 | 버전 탭 `경고` 열의 항목 ID → 항목 확인 → "선택 항목 재번역" 또는 직접 수정 → 처리 상태 `정상` |
| 수집이 안 됨 | 설정 점검: Gmail API 정상 여부, 트리거 `scheduledCollect 1개`, 진행 중인 수집. `GMAIL_QUERY`·`SUBJECT_KEYWORDS` |
| 트리거가 여러 개 | "주간 자동 수집 설치·갱신"을 다시 실행하면 1개로 정리. `continueRun`이 남아 있으면 다음 실행이 지움 |
| 뷰어가 "권한 없음" | aqara.kr 계정으로 로그인했는지. 계속되면 Workspace 관리자 정책(웹앱 공유 제한) 확인 |
| 뷰어 데이터가 옛날 것 | 상단 "데이터 기준" 시각 확인. 시트를 고치면 캐시가 지워지고, 늦어도 6시간 안에 갱신 |
| 메일 형식이 바뀌어 파싱이 틀림 | "백필 미리보기"로 확인 → 파서 수정(`src/parser/`) → 테스트 → "저장된 버전 재파싱" |
